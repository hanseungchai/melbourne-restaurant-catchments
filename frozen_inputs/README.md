# frozen_inputs

## What this folder is

Frozen copies of every external input the pipeline starts from: API pulls, downloaded
datasets and hand-made inputs. Nothing here can be regenerated by running local code.
One exception, `legacy_evidence/`: legacy files kept as evidence that concept docs cite, not
inputs (see "Legacy evidence" below), copied on 2026-10-16 before `data/` and `backup/` were
archived.

- **Source:** copied byte-for-byte from `data/` (legacy archive) on 2026-10-06. Each entry
  gives the original `data/` path. Copies keep the original modified dates.
- **Code:** API pulls were made by code recorded at git tag `legacy-final` (commit `b11551a`),
  except where an entry says the code changed after the pull.
- **Read-only:** files here are never changed, moved or deleted. A newer version of a file is
  added alongside the old one, never replacing it. Only the owner adds files; Claude keeps this
  README up to date.
- **Layout:** one folder per source or API. Every data file sits in a subfolder. A folder name
  ending in `_YYYYMMDD` (e.g. `places_nearby_scan_20260629`) carries the collection date of the
  API pull inside it; a later pull of the same API gets its own dated folder alongside.
- **Testing:** API stages are tested from these files, never by calling an API.
- **Git:** only this README is tracked. The data files are git-ignored, so they are not pushed
  to GitHub (API terms restrict sharing stored results).
- **Dates:** "downloaded" / "collected" dates are file modified dates unless the file records
  its own timestamps (then those are given, in UTC). Creation dates only record a later copy.

Not frozen here (set aside for the diagnostics stage): Legacy Nearby smoke tests, the March
2026 scan, superseded probe runs, the inner-disc recall check, and the earlier 540-pair
Routes set. Exceptions, kept as cited evidence in `legacy_evidence/`: smoke test 5 and the
2026-09-23 probe comparison tables.

## How each file was created

### Downloads

#### `osm_extract/planet_143.599,-38.893_146.327,-36.735.osm.pbf`
- **Original path:** `data/bbbike/planet_143.599,-38.893_146.327,-36.735.osm.pbf`
- **Source:** BBBike custom OpenStreetMap extract (file header: `generator: https://download.BBBike.org`)
- **Link:** https://extract.bbbike.org/ (extracts are delivered as expiring links)
- **Downloaded:** 2026-09-24
- **Version:** OSM data as of 2026-09-23 23:00 UTC (header `osmosis_replication_timestamp`).
  Bounding box 143.599, -38.893 to 146.327, -36.735 (lon, lat), as in the file name.
- **Not re-downloadable:** a new extract would contain newer OSM data. This file is the snapshot.
- The only live extract. All other extracts are deprecated.
- **Used by:** `road_graphs.build_road_graphs` (stage `map_construction`). Uncleaned later stages
  (`construct_map`, `road_density`, `r5py_pt_graph`) still read the `data/bbbike/` copy.

#### `osm_speeds/default_speeds.json`
- **Original path:** `data/OSM/default_speeds.json`
- **Source:** OpenStreetMapSpeeds project: OSM-derived default road speeds by country/state,
  road class and rural/suburban/urban density. The file uses the JSON layout the Valhalla
  routing engine reads; this project uses neither Valhalla's engine nor its speed tables
  (only Valhalla's road-density method).
- **Link:** https://github.com/OpenStreetMapSpeeds/schema (`default_speeds.json`)
- **Downloaded:** 2026-09-29
- **Version:** none recorded in the file; the repository changes over time, so the download
  date is the version marker.
- **Used by:** the `osmtable` drive speed model (`speed_graphs.enrich` via `config.OSM_SPEED_TABLE_PATH`,
  AU/VIC entry; stage `build_speed_graphs`).

- **Original path:** `data/map_pathing/od_sample_pairs.csv` (copied by the user 2026-10-09,
  byte-identical, modified date kept)
- **What it is:** the draws behind the Routes fetch above: 4,000 origin-destination pairs (origin hex
  centroid, destination venue `place_id`, accepted snap nodes, blind β = 2 raw time, departure slot),
  one row per `draw_no`. Not an API pull itself, but the fetch's other files are keyed by `draw_no`
  only, so without it the Google times cannot be tied back to their pairs.
- **Code:** `map_pathing.random_sampling` at `legacy-final` (seed `20260930`; kept only pairs
  reachable within 25 raw minutes on the blind graph at β = 2).
- **Made:** 2026-09-30 17:55 UTC (file modified date), before the fetch started.
- **Why frozen:** a redraw on the rebuilt graph can accept or reject a different pair and shift every
  later `draw_no`, which would silently attach Google times to the wrong trips. The calibration stage
  reads these draws; a fresh `random_sampling` run is only checked against them.
- **Used by:** `drive_samples.join_drive_sets` and `split_drive_pairs` via `config.ROUTES_DRIVE_DRAWS_PATH`
  (stage `sample_drive_pairs`); also the exclusion list of the second drive draw
  (`drive_samples.draw_second_drive_set`: no hex pair reused).
